# План покупки по портфелям наставников (локально, macOS, только чтение)

Скилл ТОЛЬКО ЧИТАЕТ: Google-таблицу и брокерский счёт. Никогда не выставляй и не меняй ордера — даже TP/SL; пользователь делает это сам в приложении Freedom.

Зависит от скилла `fb-portfolio`: берёт соседний `skills/fb-portfolio/tn.py`, ключи API (из `~/.zprofile`/`~/.zshrc`) и `FB_HOME/config/portfolio.ini` (классы тикеров, лимит 5%, цели 40/30/30). Все правила безопасности ключей и структура папок `FB_HOME` — из `fb-portfolio`.

## 1. Входные данные

- **Актуальная ссылка** на таблицу наставников — **обязательна, всегда бери её у пользователя в текущем запросе.** Наставники меняют ссылку каждый месяц (защита от ушедших с подписки), поэтому никогда не подставляй ссылку из прошлых разговоров, памяти или отчётов и не сохраняй её. Нет ссылки в сообщении — попроси прислать ссылку на этот месяц, ничего не запуская.
  Подойдёт ссылка на любую вкладку этой таблицы: скрипт сам находит все вкладки-портфели (архивные пропускает) и разбирает каждую. Основной портфель — «Светлое будущее» (пользователь чаще всего покупает оттуда, он получает бонус в баллах); если его в таблице нет — скрипт остановится (значит, ссылка не та).
- **Сумма** в USD (обычно $100+). Если не указана — спроси (можно одним вопросом вместе со ссылкой).

## 2. Запуск

Одна команда делает всё (все портфели таблицы + мой портфель + мои ордера + котировки брокера):

```bash
env -u TERM_SESSION_ID zsh -lic 'python3 ~/.claude/skills/fb-invest/mentors.py "<ссылка>" --amount 100' 2>/dev/null
```

Опции: `--primary "<название>"` (другой основной портфель, только по просьбе пользователя), `--fee 1.2` (комиссия на ордер; по умолчанию — медиана комиссий основного портфеля), `--recent-days 31` (окно «недавних» сделок), `--from-cash` (сумма берётся из кэша, уже лежащего на счёте, например от продаж, а не пополнения: лимит 5% и 40/30/30 считаются от текущих активов без прибавки суммы; используй, когда пользователь говорит «из кэша», «на деньги от продажи», или когда сумма явно покрыта свободным кэшем, но сначала уточни), `--max-tickers 3` (потолок бумаг в корзине; фактически не больше одной бумаги на каждые $50 суммы, чтобы комиссии не съедали покупку), `--md-dir <папка>`, `--no-save` (не писать отчёт и НЕ обновлять снимки — для пробных прогонов).

Если вывод пустой — повтори без `2>/dev/null`. Ошибки `HTTP 4xx fetching sheet` / `did not return CSV` — ссылка устарела (сменился месяц) или доступ закрыт: попроси у пользователя свежую ссылку. `Primary portfolio … not found` — ссылка не на ту таблицу. Если какой-то портфель пропал из `portfolios` — возможно, поменялась вёрстка вкладки: колонки ищутся по строке заголовков с ячейкой «Buy Sell» (`COLS` в `mentors.py`).

Результат — JSON на stdout + Markdown-отчёт `FB_HOME/reports/YYYY-MM/invest_YYYY-MM-DD_HH-MM.md` (путь — в поле `report_md`). Запуск сам подтягивает мои сделки из брокера (`journal-sync`; с `--no-save` — без записи), чтобы учесть продажи. Без `--no-save` запуск также пишет в журнал: строку в `journal/runs.jsonl` (сумма, корзина, число изменений; ссылка на таблицу НЕ пишется) и каждое изменение у наставников в `journal/mentor_changes.jsonl` — это полная история TP/SL, снимки хранят только последнее состояние.

## 3. Что в JSON

- `portfolios[]` — каждый портфель: `short` (название), `primary`, дата обновления, открытые позиции (кол-во, средняя, текущая цена, доля, рекомендация НАКАПЛИВАТЬ/ДЕРЖАТЬ, SL/TP, вид актива, шариат).
- `changes` — **по каждому портфелю: что изменилось у наставников с прошлого запуска**: `sl_tp` (старый → новый TP/SL), `rec` (смена рекомендации), `opened`, `closed`, `new_trades`. `null` — первый запуск для этого портфеля. Снимки в `FB_HOME/state/mentors/`, по одному на портфель, привязаны к названию вкладки, а не к ссылке, — сравнение переживает ежемесячную смену ссылки.
- `recent_trades` — их сделки за `--recent-days` по всем портфелям (поле `portfolio`).
- `sl_tp_check` — мои активные TP (ордер type 6) / SL (type 5) против их уровней, по каждому портфелю, где у бумаги есть уровень (поле `portfolio`; у одной бумаги в разных портфелях уровни могут различаться): `ok`, `differs`, `missing`, `qty_mismatch` (ордер не на всё количество), `mentor_closed` (вышли из бумаги во всех портфелях), `mentor_has_none`, `orphan` (стоп висит, а бумаги у меня уже нет — например, после продажи по TP остался SL; посоветуй отменить его в приложении).
- `my_realized_usd` — реализованный P&L по моим продажам (`month`, `ytd`, `all`).
- `my_recent_sales` — мои продажи за `--recent-days`: тикер, кол-во, цена, `realized_pl_usd`, `still_held`, `price_now`, `mentor_status` (`holding` — наставники ещё держат: `mentor_rec`, `mentor_tp`, `mentor_sl`, `portfolios`; `exited` — тоже вышли: `mentor_sold_date`/`price`; `never` — у них бумаги не было).
- `mentor_closed_i_hold` — наставники вышли из бумаги во всех портфелях, а у меня она ещё есть.
- `plan` — `candidates` (по тикеру, объединённо по портфелям: `portfolios`, балл, причины `why`, ограничение `blocked`), `basket` (что купить: тикер, кол-во, цена, сумма, портфели, их SL/TP), `spent`, `fees`, `left`, `class_gap_usd`, `cap_usd`.

Как считается балл: НАКАПЛИВАТЬ хотя бы в одном портфеле +3; есть в основном портфеле +2; в нескольких портфелях +0.5; их покупка за ≤31 дн. +2 (≤14 дн. +3); класс недобран до 40/30/30 — до +2, перебран — до −2; у них доля больше, чем у меня — до +1.5; цена ниже их средней — +0.5; я продал бумагу за `--recent-days` — −2 (−1, если сейчас дешевле цены моей продажи). Отсекается: нет котировки на `.US` у брокера, покупка пробьёт лимит 5%, 1 шт. дороже суммы. В корзину — только целые акции, в первую очередь НАКАПЛИВАТЬ, с резервом комиссии на каждый ордер. Класс берётся из `portfolio.ini`, иначе из вида актива наставников (Акция → stock, ETF/Фонд → index, Хедж → hedge) — для незнакомых тикеров проверь класс сам (например, золото/металлы/облигационные фонды → hedge).

## 4. Как подавать результат

По-русски, кратко, в таком порядке:

1. **Изменения TP/SL у наставников — первым блоком и заметно**, сгруппировано по портфелям. Для каждого: тикер, портфель, было → стало, и есть ли эта бумага у пользователя (тогда прямо скажи «поправьте свой ордер TP/SL на …»). Также смены рекомендаций, новые/закрытые позиции. Портфели с `changes = null` — скажи, что это первый запуск для них и снимок сохранён.
2. **Мои TP/SL против наставников** — только проблемные строки (`missing`, `differs`, `qty_mismatch`, `orphan`, `mentor_closed`) с указанием портфеля; если у бумаги в разных портфелях разные уровни — покажи оба и отметь, какой из основного портфеля. Если всё `ok` — одной строкой.
3. **Недавние сделки наставников** — короткая таблица (дата, портфель, Buy/Sell, тикер, кол-во, цена).
4. **Что купить на сумму** — таблица из `basket`: тикер, кол-во, цена, сумма, класс, портфель(и), их SL/TP (чтобы пользователь сразу поставил). Итог, комиссии, остаток. Коротко — почему именно эти (из `why`).
   Корзина скрипта — эвристика. Ты можешь предложить альтернативу своим суждением, если видишь вариант лучше по стратегии пользователя: он чаще покупает из «Светлого будущего», держит структуру 40/30/30 и лимит 5%. Например, если корзина целиком из другого портфеля, покажи рядом вариант из основного; если хедж сильно недобран — вариант, который его закрывает. Правила альтернативы: только бумаги из открытых позиций наставников, лимит 5%, целые акции, комиссии; объясни выбор в 1–2 фразах.
5. **Мои продажи** (`my_recent_sales`) — коротко: что продал, P&L, и как это соотносится с наставниками (вышел, а они держат и НАКАПЛИВАЮТ — сравни текущую цену с ценой продажи и их TP/SL; вышли вместе — ок). Если в корзине бумага, которую пользователь недавно продал, — скажи это прямо. `orphan` из `sl_tp_check` — напомни отменить висящий ордер.
6. `mentor_closed_i_hold` — упомяни, что наставники вышли из этих бумаг (решать пользователю).
7. Ссылка на md-отчёт (`report_md`).
8. Одной строкой: «Когда купите — скажите, что взяли, я сверю с брокером и запишу в журнал» (см. п.5 `fb-portfolio`).

Не давай уверенных инвестиционных рекомендаций; в конце напомни, что это не финансовый совет, а разбор по данным наставников и правилам пользователя.
