# Консультант по портфелю Freedom Broker (только чтение)

Скилл ничего не покупает и не продаёт: ордера пользователь ставит сам в приложении Freedom. Данные берёт через `fb-portfolio`
(`tn.py`, те же ключи и правила безопасности — значения ключей не выводить никогда), правила — из `config/portfolio.ini`,
наставников — из `state/mentors/` (снимок `fb-invest`). Скрипт: `~/.claude/skills/fb-advisor/advisor.py` (stdlib, Python 3.9+).

Методика собрана из открытых скиллов: `portfolio-review` из [ai-berkshire](https://github.com/xbtlin/ai-berkshire) (вопросы
«купил бы сейчас?», состояние тезиса, балл 1–10) и набора [tradermonty](https://github.com/tradermonty/claude-trading-skills)
(лежит в `skills/vendor/tradermonty/`, см. `VENDOR.md`). Чужие скиллы используются как инструменты внутри этого процесса.

Запуск — всегда через login-shell, иначе не будет ключей:

```bash
env -u TERM_SESSION_ID zsh -lic 'python3 ~/.claude/skills/fb-advisor/advisor.py <команда>' 2>/dev/null
```

| Команда | Что делает |
|---|---|
| `prep [--offline]` | досье по каждой позиции → stdout и `state/advisor/dossier.json` (перезаписывается) |
| `save <verdicts.json>` | проверяет вердикты, пишет `reports/YYYY-MM/advisor_*.md`, дописывает `journal/advice.jsonl` и `runs.jsonl` |
| `check TICKER --amount 100 [--price P --tp T --sl S --class stock\|index\|hedge --from-cash --max-positions 25 --sell T[:USD] ...]` | чек-лист перед покупкой: PASS / WARN / BLOCK. `--sell` (повторяемый) — продажи, которые сделаешь до покупки: учитываются в доле, теме, классе и числе позиций |
| `scorecard [--offline] [--min-days 7]` | прошлые советы против текущей цены: доля попаданий по каждому вердикту |

## Досье (`prep`)

Онлайн: позиции, стоп-ордера, облигации, синхронизация сделок (`journal-sync`). Если API не отвечает, скрипт сам переходит
в офлайн-режим (`source: "offline"`, причина — в `api_error`): берёт последний снимок `fb-portfolio` из `runs.jsonl` и сделки
после него, а KZT переводит по курсу НБК на дату снимка. **Тогда цены устаревшие — так и скажи пользователю.** При ответе
`Api key has expired` пользователь должен выпустить новый ключ в кабинете Tradernet и заменить его в `~/.zprofile`.
Средняя цена в офлайн-режиме — себестоимость по сделкам, делённая на текущее количество (сплиты учтены), и обычно совпадает
с брокерской до 0.1 п.п. Погашение KZ-облигаций в офлайн-режиме не видно — бери его из последнего md-отчёта `fb-portfolio`.

По каждой позиции: доля, P&L, класс, темы, с какой даты держу, мои TP/SL, рекомендации наставников, `flags`
(`over_limit`, `near_limit`, `small`, `deep_loss`, `no_mentor`, `below_mentor_sl`, `theme_full`, `matured`,
`sold_recently`, `unclassified`), `hints` (механические подсказки) и `priority` — порядок разбора.
В `summary`: число позиций и эффективное число (1/Σw²), доля топ-5 убыточных в общем убытке, разрывы 40/30/30 и темы.

## Режим A. Полный разбор портфеля

1. `prep`. Если офлайн — одной строкой: почему и на какую дату цены.
2. **Рынок** (по `~/.claude/skills/market-environment-analysis/SKILL.md`, коротко): S&P 500, Nasdaq, VIX, доходность UST 10Y,
   DXY, золото, нефть, USD/KZT, индекс KASE → режим `risk-on` / `neutral` / `risk-off` и 2–3 фразы, что это значит для портфеля.
3. **Разбор каждой позиции** в порядке `priority`. Позиций много, поэтому параллель: субагенты (Task / `delegate_task`) пачками
   по 6–8 тикеров с брифом из `references/research-brief.md` — в него вставь строки досье этих тикеров. Каждый возвращает JSON
   по схеме из брифа. Облигации (`research: "light"`) разбирай сам: эмитент, купон, погашение, риск дефолта, ликвидность.
   Для глубокого разбора одной бумаги США — `~/.claude/skills/us-stock-analysis/SKILL.md`, для влияния события —
   `scenario-analyzer`, для графика от пользователя — `technical-analyst`.
4. **Вердикты** — сам, по фактам субагентов и правилам ниже. Проверь ссылки и цифры, которые выглядят странно.
5. Запиши JSON (схема ниже) во временный файл по **абсолютному** пути и передай его в `save` тем же путём
   (`$TMPDIR` у инструмента записи и у shell может отличаться — `save` тогда молча не найдёт файл). При `errors` исправь
   и повтори; `warnings` — покажи. Затем удали временный файл.
   Перестановки (продал A → купил B) проверяй `check B --from-cash --sell A ...`, иначе лимиты темы и класса считаются
   без учёта продаж. Бумаги без класса (`unclassified`) завышают разрыв по классам — сначала предложи их классы.
6. Ответ пользователю (по-русски, кратко):
   - **Главное** — 3–5 пунктов: откуда минус (`top5_losers_share_pct`, распыление, недобор хеджа), что меняет ситуацию.
   - **План действий по порядку**: сначала ВЫЙТИ / СОКРАТИТЬ / ЗАМЕНИТЬ (что освобождается, сколько $), затем куда направить
     кэш (ДОКУПИТЬ и недобранные классы), какие TP/SL поставить. Каждое действие — тикер, кол-во, уровень.
   - Таблица вердиктов: тикер, вердикт, балл, P&L %, одна фраза почему. Где вердикт расходится с основным портфелем
     наставников («светлое будущее»), скажи это прямо и почему.
   - Ссылка на md-отчёт. «Когда сделаете — скажите, я сверю с брокером и запишу в журнал» (`fb-portfolio`, п.5).
   - В конце: это разбор по открытым данным, а не финансовый совет.

### Правила вердиктов

- **Средняя цена — не аргумент.** «Отыграется до средней» — якорение. Решает один вопрос: *купил бы я эту бумагу сейчас,
  по этой цене, на эту долю?* Нет, и тезис ослаб или сломан → СОКРАТИТЬ / ВЫЙТИ / ЗАМЕНИТЬ, даже в минусе.
- `ДОКУПИТЬ` — только если тезис цел, `would_buy_today: true`, после покупки соблюдены лимиты (5% на бумагу, 10% на тему,
  класс не перебран), есть уровень входа и SL (цена, при которой тезис сломан).
- `over_limit` → СОКРАТИТЬ до лимита, либо ДЕРЖАТЬ с явной причиной и запретом докупать.
- `small` (<1%) — на итог не влияет, но отнимает внимание: ДОКУПИТЬ до ≥2% или ВЫЙТИ / ЗАМЕНИТЬ. ДЕРЖАТЬ мелкую — только с причиной.
- Пересечения (FXI + MCHI + KWEB, GLD + IAU и т.п.) → предложи оставить один инструмент (ЗАМЕНИТЬ / СОКРАТИТЬ дубль),
  это уменьшает число позиций без потери идеи.
- Замену (`replace_with`) бери в первую очередь из открытых позиций наставников, иначе широкий ETF того же класса.
- Отдельная акция с `deep_loss`, без наставников и со сломанным тезисом → по умолчанию ВЫЙТИ.
- Ориентир — не больше ~25 позиций при таком размере счёта: комиссия ~$1.2 на ордер, а доли меньше 1–2% не двигают результат.
- Хедж ниже цели 30% — освобождённый кэш в первую очередь закрывает этот разрыв.
- `confidence: low`, если данных мало (KZ-бумаги, малые компании, нет свежей отчётности) — и скажи это.
- Нет данных — пиши «нет данных». Цены, мультипликаторы и даты не выдумывать.

### Схема `verdicts.json`

```json
{
  "as_of": "2026-11-02T18:00:00",
  "summary": "2–5 фраз",
  "market": {"regime": "risk-on|neutral|risk-off", "notes": "..."},
  "portfolio_actions": ["Выйти из VNRX, DUOL — освободится ~$180", "..."],
  "positions": [
    {"ticker": "ORCL.US", "verdict": "ДЕРЖАТЬ", "score": 6, "confidence": "medium",
     "thesis_status": "цела|ослабла|сломана", "would_buy_today": true,
     "thesis": "зачем держу", "reasons": "факты за вердикт", "risks": "что сломает тезис",
     "action": "не докупать до отчёта 10.12; SL 105", "levels": {"add_below": 115, "tp": 170, "sl": 105},
     "replace_with": null, "replace_price": null, "sources": ["https://..."]}
  ],
  "buy_ideas": [{"ticker": "IAU.US", "amount_usd": 100, "entry": 75, "tp": 90, "sl": 68, "check": "PASS", "why": "..."}]
}
```

`ticker` — как в досье; вердикт обязателен для каждой позиции (иначе `warnings`); `score` — целое 1–10;
для ЗАМЕНИТЬ обязателен `replace_with` (и, по возможности, `replace_price` — цена замены сейчас, нужна для `scorecard`).

## Режим B. «Что купить сейчас» / «стоит ли брать X»

1. `prep`, если досье старше суток.
2. Рынок — коротко, как в A.2. В `risk-off` по умолчанию: меньшая сумма, частями, приоритет — хедж и широкие индексы.
3. Кандидаты: бумага, которую назвал пользователь; НАКАПЛИВАТЬ у наставников (свежий `fb-invest`, если пользователь дал ссылку
   на таблицу, иначе снимок `state/mentors/` с датой); ДОКУПИТЬ из `journal/advice.jsonl` за ≤30 дней; недобранный класс.
   Новую бумагу разбирай по `references/research-brief.md`.
4. **Момент входа — честно:** рынок никто не угадывает. Правила: делить покупку на 2–3 части; в восходящем тренде брать
   на откате к поддержке или 50-дневной средней; не брать отдельную акцию за ≤5 торговых дней до отчёта; не ловить падающий
   нож (ниже 200-дневной средней и продолжает падать без смены тезиса). Для каждой идеи: зона входа, TP, SL.
5. По каждой идее — `check`. BLOCK — не предлагать (объясни почему); WARN — показать предупреждения.
   Только целые акции; размер от риска — по `~/.claude/skills/position-sizer/SKILL.md`, если пользователь хочет.
6. Таблица: тикер, кол-во, цена входа, сумма, TP, SL, статус чек-листа, почему. Сохранить разбор можно через `save`
   с `positions: []` и заполненным `buy_ideas` (предупреждения о позициях без вердикта — ожидаемо).

## Режим C. «Как сработали советы»

`scorecard`: по каждому совету старше `--min-days` дней — цена тогда и сейчас; попадание: ДОКУПИТЬ / ДЕРЖАТЬ — цена выросла
больше 2%, СОКРАТИТЬ / ВЫЙТИ — упала больше 2%, ЗАМЕНИТЬ — замена обогнала исходную бумагу; движение меньше 2% не считается.
Показывай честно, в том числе промахи; при малом числе советов скажи, что выборка мала для выводов.

## Журнал

`journal/advice.jsonl` — только дописывать: одна строка на позицию на каждый `save` (вердикт, балл, цена, уровни, действие).
Это основа `scorecard` и ответов на вопрос «что ты советовал по X». В журнал не писать ключи, логин и ссылку на таблицу наставников.
