# zm-import — выписка → Дзен-мани

Корень проекта: `zen-money-accounting/` (папка над `skills/`). Перед работой прочитай `zen-money-accounting/CLAUDE.md`.

## Шаги

1. **Выписка → `inbox/`.** Только туда, никуда больше не копировать.
2. **Разбор:**
   ```bash
   cd zen-money-accounting
   .venv/bin/python skills/zm-import/parse_statement.py inbox/<file>.pdf --summary   # банк, счёт, период, сверка
   .venv/bin/python skills/zm-import/parse_statement.py inbox/<file>.pdf             # + операции
   ```
   Если нет `.venv`: `python3 -m venv .venv && .venv/bin/pip install -r skills/zm-import/requirements.txt`.
   Вывод не сохранять в файлы. `checks_ok: false` → стоп, разобраться, почему не сходится (не импортировать).
   `ok: null` у Freedom = в типе есть валютные операции; смотри `implied_rate` — должен быть правдоподобным курсом.
3. **Счёт:** `rules/accounts.json` (`"<bank>:<маска>"` → счёт Дзен-мани). Нет записи — `list_accounts`, спросить, сохранить.
4. **Дедуп.** Синхронизации банков с Дзен-мани НЕТ: всё вносит пользователь вручную или Claude по его просьбе.
   Поэтому часть операций уже внесена руками (часто с комментариями) — их не дублировать, остальное занести.
   Выгрузка операций Дзен за период выписки — через Claude Code headless, сырым потоком (не пересказом модели):
   ```bash
   S=~/.hermes/cache/scratch/zm; mkdir -p $S   # временно, удалить после импорта
   claude -p "Вызови mcp__zenmoney__list_transactions с <from> по <to> для счёта <zen_id>, догрузи все страницы по nextCursor. Ничего не изменяй." \
     --allowedTools "mcp__zenmoney__list_transactions" --output-format stream-json --verbose > $S/stream.jsonl
   ```
   Из `stream.jsonl` взять `tool_result`; если результат большой, Claude Code сохраняет его в
   `~/.claude/projects/<repo>/<session>/tool-results/*.txt` — путь есть в тексте результата.
   Затем: `python3 skills/zm-import/match.py st.json zen.json <zen_id>` → `matched` / `missing` / `extra`.
   - USD-операции Freedom часто внесены в тенге без `originalAmount` → матчатся вторым проходом по медианному курсу
     (`via: fx`), иногда две операции дня = одна запись (`via: fx-sum`). Мелкие суммы (< $2) уходят за допуск из-за
     округления — проверять глазами по дате и контрагенту.
   - `extra` — то, что есть в Дзен, но не в выписке: ручные записи пользователя (долги, «Корректировка»,
     разница курсов, разнесение одной операции на части). Это не ошибки — не трогать без вопроса.
   - Пара «покупка −X и возврат +X в один день» = отмена → `skipped`, не заносить.
5. **Переводы между своими счетами** — один перевод, а не расход + доход. Известные пары — в `rules/accounts.json → transfers`.
   Перевод уже заведён со стороны другого счёта (другая выписка / ручной ввод) → `duplicate`.
6. **Категория:** `rules/merchants.json` (регэксп по `details` → категория). Нет правила и неочевидно — спросить;
   ответ записать правилом с `"source": "user"`. Своё предположение помечать `"source": "guess"` и показывать в сводке.
7. **Решение.** Однозначное (правило `source: user`/`history`, свой счёт, отмена) — заносить сразу.
   Переводы людям, пополнения от людей, расхождения сумм с уже внесённым — не трогать, спросить.
   Ограничения из `rules/merchants.json → constraints` проверять и для уже внесённых записей.
8. **Запись:** собрать payload в scratch (`requestId` = новый uuid4; для импорта — `originalPayee` + `merchantId`
   из истории; валюта — `amount` в KZT по курсу банка того же дня из сматченных fx-пар + `originalAmount/Instrument`),
   затем `claude -p "Вызови mcp__zenmoney__upsert_transactions ровно один раз с этими аргументами, дословно: <json>"
   --allowedTools "mcp__zenmoney__upsert_transactions" --output-format stream-json --verbose`.
   В потоке сравнить `tool_use.input` с payload (должны совпасть) и взять `id` из `results`. Пачки ≤ 200.
   Правка контрагента/категории существующей записи: `{"id": ..., "merchantId": ...}` без money-сторон.
9. **Журнал** (только дописывать): строка на операцию в `journal/decisions.jsonl`, строка на файл в `journal/imports.jsonl`.
10. **Удалить PDF** из `inbox/`, закоммитить `journal/` и `rules/`.

## Особенности банков

- **Kaspi Gold:** сводка сходится точно по всем типам. Возвраты приходят как `Покупка` с `+` (пара ±одинаковая сумма в один
  день = отмена → обе `skipped`). «Перевод на свой счет» / «Поступление со своего счета» — движения внутри Kaspi
  (Депозит, Red, Кредит). «На карту Freedom Finance Bank*7488» — перевод на Freedom.
- **Freedom Super Card:** мультивалютная карта (KZT, USD…). `Сумма в обработке` = ещё не проведена (`status: pending`),
  в следующей выписке станет `Покупка`. «Прием вклада» / «Перевод вклада по Договору №*XXXX» — движения с депозитами.
  `FRPAY FREEDOM BROKER` — пополнение брокерского счёта. Строки, порванные границей страницы, парсер склеивает.

## Нельзя

Хранить PDF и выгрузки; писать в файлы IBAN, ИИН, ФИО, остатки; вызывать `delete_transactions` без явной просьбы
по конкретным операциям.
